# SteamUltraLite — план разработки

## Переписывание на Rust

Новый Windows-клиент находится в `apps/ultralite`. Он собирается отдельно
командой `cargo build --locked --release -p steam-ultralite`. Старый desktop
сохранён как база сравнения. Официальный Steam нужен для игр, которым
требуются его DRM, Steamworks или античит. Прямой запуск разрешается для
игр с подтверждённой совместимостью. Лицензии проверяет Steam.

В новой сборке исключаются собственная игровая DLL, запись в реестр Steam,
модификация игровых бинарников, внедрение в процессы и фоновые службы
магазина, сообщества, обновлятора и оверлея. Проверки проводятся с включённой
защитой и сначала на тестовом аккаунте.

1. Локальная библиотека и поиск. Чтение манифестов с нескольких дисков,
   поиск по названию и AppID, обработка битых и незавершённых манифестов.
   В пакете отсутствуют старый desktop, сетевой клиент и игровая DLL.
2. Вход и полная библиотека. Проверить Steam Guard, получение лицензий и
   выход на отдельном аккаунте. Токены хранятся в Windows Credential Manager.
3. Установка и удаление. Приёмка на законно доступной тестовой игре.
   Проверить восстановление загрузки и ограничение удаления папкой игры.
4. Запуск игр. Проверить прямой запуск совместимых игр и официальный fallback
   для остальных. Учесть 32- и 64-битные игры.
5. Steam Cloud. Проверить синхронизацию подходящей игры и конфликт с
   сохранением обеих копий. Подтвердить отсутствие секретов в журналах.
6. Замеры, антивирус и релиз. Проверить граф зависимостей, размер, память,
   старт и простой по прежней методике. Собрать portable ZIP после приёмки.

библиотеки не скрывает игры на других дисках. Кнопки установки, удаления
и запуска остаются недоступны до этапов 3 и 4: безопасная загрузка,
проверка границы удаления и совместимость запуска ещё не приняты.

## История реализации на базе SteamInRust 0.15.0

Цель: неофициальный минималистичный клиент библиотеки Steam для Windows 10/11 x64 на основе SteamInRust 0.15.0. Сохранить MIT и авторские уведомления. Ветка main остаётся базой для синхронизации с upstream.

## MVP
- Вход, Steam Guard, QR, выход; библиотека, текстовый список по умолчанию, поиск, фильтр установленных, избранное.
- Установка, обновление, отмена загрузки, удаление, запуск, облачные сохранения и офлайн в пределах поддерживаемых upstream возможностей.
- Для игр с античитом сохранить официальный путь запуска. Не менять проверку лицензий, DRM и античит.
- Убрать магазин, новости, сообщество, чаты, рынок, профили, Big Picture, плагины, трейлеры, оверлей из UI и по возможности из графа зависимостей. Не удалять игровые API, необходимые для совместимости.

## Этапы
1. Собрать неизменённый upstream: cargo build --locked --release; cargo test --workspace; cargo run -- --demo. Проверить актуальный toolchain и инструкции сборки Windows GNU/MinGW. Зафиксировать результаты и SHA. Не выдавать отсутствие сборки за успех.
2. Аудит apps/desktop, crates/client, crates/ui и зависимостей store, video, voice, plugins, extensions. Выявить фоновые задачи, обработчики событий и связи с игровым DLL. Использовать cargo tree -e features. Проверить безопасность хранения токенов, сетевые адреса и механизм обновления. Отключить обновления из upstream в форке, пока не настроен собственный доверенный канал.
3. Сделать минимальный экран библиотеки: текстовый список, строка поиска, фильтр установленных, избранное, кнопки играть/установить/обновить/удалить, компактный статус загрузки, настройки и выход. Обложки опциональны, загружаются лениво. Без анимаций, сетевых запросов за новостями и автоматического воспроизведения.
4. Добавить Cargo feature ultralite либо эквивалентную изоляцию после аудита; отключить ненужные службы при старте и исключить зависимости из release-сборки, где безопасно. Сохранить возможность синхронизации upstream. Не ломать протоколы и совместимость ради размера.
5. Профилировать релиз на одинаковом ПК, аккаунте и библиотеке: private bytes после 60 с покоя, рабочий набор отдельно, CPU в процентах одного ядра, холодный старт до окна и готовности списка, размер распакованной сборки, число процессов. Минимум 5 прогонов, медиана. Цели: 30–60 МБ private bytes, окно до 1 с, CPU до 0.1% ядра; это ориентиры, не обещания. Сравнить с неизменённой версией 0.15.0, не с опубликованными замерами 0.10.0.
6. Проверить demo, библиотеку большого размера, отсутствие сети, загрузку с паузой и возобновлением, облачные конфликты, запуск 32/64-битных игр и официальный fallback. Проверить отсутствие секретов в логах. До аудита не использовать основной аккаунт.
7. Собрать portable ZIP с необходимыми DLL, лицензиями, контрольными суммами, инструкцией, предупреждением о неофициальном статусе и ограничениях совместимости. Не использовать upstream релизы как релизы форка.

## Критерии приёмки
- Работают поддерживаемые upstream базовые сценарии библиотеки; все тесты и результаты сборки документированы.
- В UltraLite не запускаются удалённые службы, отсутствуют ненужные запросы и страницы; cargo tree подтверждает исключение опциональных тяжёлых зависимостей там, где это безопасно.
- Нет регрессии лицензирования, облачных сохранений и античит fallback. Реальные показатели производительности опубликованы с методикой.
- Нет Chromium/WebView. Русский и английский интерфейс. Основная ветка не изменяется до проверки.
